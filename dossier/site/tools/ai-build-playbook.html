AI Build Playbook — provision the JR-Tech Odoo 19 instance via MCP

The deterministic runbook a future AI agent follows to stand up the JR-Tech Solution Sdn Bhd Odoo 19 database end-to-end: connect over MCP / XML-RPC, install modules in dependency order, load master data, generate demo transactions, then validate. Every step is idempotent and keyed to the artifacts under /odoo/seed, /odoo/plan and /odoo/playbook.

Connection bootstrap

Two transports are supported. Prefer MCP tools when available; fall back to XML-RPC for bulk loads. Store the resolved uid and reuse it.

# --- XML-RPC fallback (Python) ---------------------------------
import xmlrpc.client, os
URL = os.environ["ODOO_URL"]        # https://jrtech.odoo.com
DB  = os.environ["ODOO_DB"]         # jrtech
USER= os.environ["ODOO_LOGIN"]      # admin / build-bot@technext.asia
KEY = os.environ["ODOO_API_KEY"]    # developer API key, NOT password

common = xmlrpc.client.ServerProxy(f"{URL}/xmlrpc/2/common")
uid    = common.authenticate(DB, USER, KEY, {})
assert uid, "P3 FAILED: authentication returned 0"
models = xmlrpc.client.ServerProxy(f"{URL}/xmlrpc/2/object")

def call(model, method, *args, **kw):
    return models.execute_kw(DB, uid, KEY, model, method, list(args), kw)

1 · Build sequence overview

The build is strictly ordered because Odoo enforces hard foreign-key dependencies (a BoM needs products; a product needs UoM & categories; a sale order needs a customer and a pricelist). The agent executes the phases top-to-bottom and never proceeds past a failed validation gate.

3 · Master-data load order

Load strictly in this sequence. Each stage references external IDs created by the previous stage, so the dependency chain companies → users → products → BoMs → partners → pricelists → transactions must hold.

  1. Companies & localization — set res.company for JR-Tech Solution Sdn Bhd: name, SSM 200901013633, Penang address (556-Y, Jalan Sultan Azlan Shah, 11700 Gelugor), MYR currency, fiscal year, country = MY. Apply the MY chart of accounts and SST tax mapping. Configure the MyInvois TIN & certificate fields. Seed file: /odoo/seed/01_company.json.
  2. Users & access rights — create res.users for the six personas (Sales rep, Workshop/fabrication, Field-service tech, Storekeeper, Finance, Admin), assign security groups per the Staff Guides roles. Seed: /odoo/seed/02_users.json. Idempotency key = login email.
  3. Reference data — UoM (unit, kg, L, hour, m²), product categories (Fabrication, Equipment, Rental Assets, Chemicals, Service), analytic plans (one analytic account per business line), accounting journals, and SST taxes (Sales 10% / 5% · Service 8%). Seed: /odoo/seed/03_reference.json.
  4. Products & variants — fabrication items (custom SS worktable, exhaust hood), equipment for sale & rental (induction range, dishwasher), chemical SKUs (dishwash detergent, rinse aid, pool chlorine), and service products (maintenance hour, grease-trap service). Tag each with its category & analytic default. Seed: /odoo/seed/04_products.json.
  5. BoMs & work centers — define mrp.bom for fabricated products (e.g. SS worktable = sheet + frame + labour) and mrp.workcenter (Cutting, Welding, Assembly, QC). References product external IDs from stage 4. Seed: /odoo/seed/05_boms.json.
  6. Partners — customers (hotels, restaurants, central kitchens, hospitals, condos) and vendors (steel supplier, chemical importer). Set MY TIN, payment terms, pricelist link. Seed: /odoo/seed/06_partners.json.
  7. Pricelists, rental & subscription plans — MYR pricelists with customer-tier rules, sale.temporal.recurrence rental durations, and sale.subscription.plan monthly resupply. Seed: /odoo/seed/07_pricing.json.
Hard rule: never create a transaction (stage 9) before all of stages 1–7 validate. A sale order line silently fails or mis-prices if its product, customer or pricelist external ID is missing.

Generic idempotent upsert pattern

def upsert(model, xmlid, vals):
    # xmlid like "jr_seed.product_ss_worktable"
    module, name = xmlid.split(".",1)
    found = call("ir.model.data","search_read",
        [[["module","=",module],["name","=",name]]],{"fields":["res_id"]})
    if found:
        rid = found[0]["res_id"]
        call(model,"write",[rid],vals)          # update in place
    else:
        rid = call(model,"create",vals)            # create new
        call("ir.model.data","create",{
            "module":module,"name":name,"model":model,"res_id":rid})
    return rid
