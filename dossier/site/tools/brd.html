1 · Purpose & scope

JR-Tech operates four interlocking F&B-engineering business lines on spreadsheets, WhatsApp and disconnected point tools. This project replaces those with a single Odoo 19 Enterprise platform spanning lead-to-cash, fabrication, rental, field service, chemical subscriptions and finance — Malaysia-compliant (SST, MyInvois) and AI-ready.

In scope

  • CRM & Sales across all four lines
  • Manufacturing (stainless-steel fabrication, MTO)
  • Inventory & Purchase
  • Rental of equipment & dishwashers
  • Field Service, Maintenance & Repair (incl. grease-trap / tanker)
  • Subscriptions (recurring chemical resupply)
  • Accounting: localized CoA, SST, MyInvois e-invoicing, analytic by line
  • Opening-balance & master-data migration
  • Reporting / dashboards & role-based training

Out of scope (this phase)

  • E-commerce / customer web portal storefront
  • Payroll & full HR (deferred to a later phase)
  • Manufacturing shop-floor IoT / machine integration
  • Multi-currency (MYR only at go-live)
  • Custom mobile app beyond standard Odoo mobile
  • Historical transaction migration beyond opening balances & open items

7 · Assumptions & constraints

  • Odoo 19 Enterprise on Odoo.sh (Custom plan) — per Odoo Platform.
  • Single company, single currency (MYR), single legal entity at go-live.
  • JR-Tech provides clean master data (products, customers, opening balances) on agreed templates.
  • Named business users available for workshops, UAT and training.
  • MyInvois TIN, digital certificate & LHDN onboarding completed by JR-Tech with TechNext guidance.
  • Customisation favours configuration / Studio over custom code.

9 · Use-case scenarios

The functional requirements above are validated against six end-to-end scenarios — one per business flow — each written as actor · trigger · main flow · alternates · post-condition, grounded in the seed data (137 products, 46 customers, 12 BoMs). These are the scripts the Demo Walkthrough rehearses.

UC-01 · Fabrication quote → make-to-order → SST e-invoice

ActorSalesperson, Workshop lead, Finance
TriggerHotel customer (e.g. cust_*, hotel archetype) requests a custom stainless prep table
Main flowQuote built from a fabricated product carrying a BoM (prod_fab_*, one of 12 boms.csv records) → confirm SO → MO auto-created (mrp.production) → components consumed (prod_raw_*) via Cutting→Welding→Assembly→QC → delivery → invoice with SST-S-10 → MyInvois submission
AlternateComponent short → reorder rule raises PO; quote re-priced if steel cost moved
Post-conditionPosted account.move with valid MyInvois UIN; actual job cost reconciled to quoted margin
CoversFR-SAL-001/003, FR-MRP-001/003/004, FR-ACC-002/003

UC-02 · Equipment rental → return → duration billing

ActorSalesperson, Storekeeper, Finance
TriggerCatering customer needs a dishwasher for a 14-day event
Main flowCheck availability on rental calendar → rental contract (rental_contracts.csv, is_rental) with deposit → pickup picking → return picking → bill duration at Service Tax 8%
AlternateLate return → late fee line added; damage on inspection → repair order raised
Post-conditionAsset back in available pool; rental revenue + any late/damage fees invoiced
CoversFR-RNT-001/002/003, FR-INV-003

UC-03 · Field-service dispatch → mobile capture → auto-invoice

ActorDispatcher, Technician, Finance
TriggerCustomer reports a grease-trap service due (service_tasks.csv, kind=field_service)
Main flowFSM task created on "JR Field Service" project → assigned to employee (employees.csv) + scheduled → tech sees asset history on mobile → logs time + parts → captures photo + signature → auto-invoice with Service Tax 8%
AlternateWrong/insufficient parts → task rescheduled; warranty job → zero-rated labour line
Post-conditionSigned worksheet stored; billable time + parts captured; preventive plan set for next visit
CoversFR-FSM-001/002/003, FR-MNT-001, FR-REP-001

UC-04 · Chemical subscription resupply cycle

ActorSubscriptions owner, Storekeeper, Finance
TriggerMonthly/Quarterly plan renewal date reached (subscriptions.csv, sale.subscription.plan)
Main flowRecurring rule fires → SO + delivery generated for chemical SKUs (subscription_lines.csv) → reorder rule replenishes warehouse stock → recurring invoice at SST-S-5/10
AlternateQuantity upsell mid-term → MRR recalculated; non-payment → churn flag
Post-conditionCustomer resupplied with no manual order; MRR + churn metrics updated
CoversFR-SUB-001/002/003, FR-INV-002

UC-05 · Demand-driven procurement & 3-way match

ActorStorekeeper / buyer, Finance
TriggerReorder point breached or MO raises component demand (reordering_rules.csv)
Main flowRFQ → PO to vendor (vendors.csv) → receipt picking → vendor bill matched 3-way (PO = receipt = bill) → payment per supplier payment term
AlternatePrice/qty variance on bill → blocked for review; partial receipt → backorder
Post-conditionStock received and valued; controlled AP with full spend visibility
CoversFR-PUR-001, FR-INV-001/002

UC-06 · Period close → SST return → analytic P&L

ActorFinance / bookkeeper, Director
TriggerMonth-end reached
Main flowBank feed reconciled (payments.csv against invoices.csv) → AR follow-up run → SST output/input summarised → close checklist completed → P&L filtered by analytic (business line)
AlternateUnreconciled item → suspense + exception list; failed MyInvois doc → resubmit
Post-conditionPeriod locked; SST-02 return figures ready; per-line margin visible to the Director
CoversFR-ACC-001/004/005/006
